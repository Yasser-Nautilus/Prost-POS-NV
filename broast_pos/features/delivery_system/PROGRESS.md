## Overview

The delivery system manages the full lifecycle of delivery drivers and their trips, from clock-in through trip assignment, delivery confirmation, and financial settlement. It includes per-trip and daily settlement with cash ledger integration.

---

## Driver Lifecycle

### Driver Attendance

**Status:** Implemented

| Operation | Description |
|---|---|
| Clock In | Driver marked as `AVAILABLE`, attendance record created |
| Clock Out | Driver marked as `OFF_DUTY`, attendance record closed |
| Status Query | List available, on-delivery, and off-duty drivers |

#### DriverStatus (Enum)
- `AVAILABLE` — Clocked in, ready for assignments.
- `ON_DELIVERY` — Currently on a delivery trip.
- `OFF_DUTY` — Clocked out.

## Trip Management

### Trip Lifecycle

**Status:** Implemented

```
Create Trip (assign driver) → Pick Up → Deliver → Settle
```

| Operation | Method | Description |
|---|---|---|
| Assign Trip | `assign_trip()` | Links order to driver, sets driver status to `ON_DELIVERY` |
| Mark Picked Up | `mark_picked_up()` | Records pickup timestamp |
| Mark Delivered | `mark_delivered()` | Records delivery timestamp, updates order via OrderService |
| Get Unsettled | `get_unsettled_trips()` | Lists trips pending settlement |

### Order Integration

- Delivery status transitions (`OUT_FOR_DELIVERY`, `DELIVERED`) route through `OrderService.update_order_status()` to enforce the centralized state machine.
- The `DeliveryService` does NOT independently change order status — it delegates to `OrderService`.

> [!NOTE]
> A circular dependency exists between `DeliveryService` and `OrderService`. It is resolved by post-construction injection in `main.py` (line 144): `delivery_service._order_svc = order_service`.

## Driver Settlement

### DriverSettlementService (`driver_settlement_service.py` — 543 lines)

**Status:** Implemented

#### Settlement Preview
- Calculates what a driver owes/is owed without committing.
- Shows per-trip breakdown: order total, delivery fee, amount collected, amount to remit.

#### Per-Trip Settlement
- Settles a single trip.
- **Server-side calculation:** `amount_to_remit = amount_collected - delivery_fee`.
- Creates a `DriverSettlement` record.
- Creates a `DRIVER_REMITTANCE` cash ledger entry.
- Marks the trip as settled.

#### Daily Settlement
- Batch-settles all unsettled trips for a driver in a single operation.
- Each trip gets its own settlement record and ledger entry.
- Uses atomic transactions.

#### Guards
- **Duplicate prevention:** Rejects settlement if trip is already settled.
- **In-transit guard:** Rejects settlement of trips with `OUT_FOR_DELIVERY` status (must be delivered first).

#### Ledger Integration
- `DRIVER_REMITTANCE` entries record cash returned to the register by the driver.
- `DRIVER_FEE_PAYOUT` entries are generated by `BusinessDayService` during business-day close for delivery fee payouts.
