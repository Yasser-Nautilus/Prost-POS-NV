# 📊 feature/reports — PROGRESS

## 🎯 Goal

Provide **accurate, reproducible financial summaries** for daily operations. The daily report is the source of truth for the manager at end of day.

---

## ✅ Tasks

### 1. Aggregate Orders by Type

- **What**: Group completed orders by order type with count and revenue
- **Details**:
  - Query all non-cancelled orders for the shift/date
  - Group by `order_type`: صالة, تيك اواي, دليفري, استلام محل
  - For each type: count of orders, total revenue (sum of order totals)
  - Include grand total: total order count, total revenue
- **Why**: This is the core data for the daily summary receipt. Must be 100% accurate — any discrepancy means financial trust is broken.
- **Touches**: `core/services/report_service.py`, `data/repositories/order_repository.py`
- **Status**: `Not started`

### 2. Daily Summary Generation

- **What**: Produce a complete shift summary data structure
- **Details**:
  - Input: shift_id or date range
  - Output: structured data containing:
    - Period: opened_at, closed_at (or current time if shift still active)
    - Breakdown: list of `{type, count, revenue}` dicts
    - Grand total: `{total_orders, total_revenue}`
  - Data is returned as a dict/dataclass — NO print formatting here
  - Print formatting is handled by `receipt_templates.py`
- **Why**: Separating data generation from print formatting means the same data can be displayed on screen, printed, or exported to CSV without duplication.
- **Touches**: `core/services/report_service.py`, `core/services/financial_service.py`
- **Status**: `Not started`

### 3. Print Integration

- **What**: Send formatted summary to thermal printer
- **Details**:
  - Connect Reports view "Print" button to `printer_manager.print_shift_summary()`
  - Pass the summary data generated by report_service
  - Print to current cashier's printer
  - Silent operation — no dialogs
- **Why**: The printed receipt is what the manager physically keeps. It must match the exact format from the provided photo.
- **Touches**: `ui/views/reports_view.py`, `infrastructure/printing/printer_manager.py`
- **Status**: `Not started`

### 4. Consistency Checks

- **What**: Ensure report totals match actual database sums
- **Details**:
  - Cross-validate: sum of individual order totals == reported grand total
  - Prevent double-counting: cancelled orders excluded, in-progress orders handled correctly
  - Handle edge cases: orders created before shift but paid during shift
  - Show warning if calculated total doesn't match expected total
- **Why**: Financial reports must be trustworthy. A 1-pound discrepancy over time erodes trust in the system.
- **Touches**: `core/services/report_service.py`
- **Status**: `Not started`
